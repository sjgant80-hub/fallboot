storage · per-tool breakdown

Every URL fetched by Bundle lives in the browser's Cache Storage under fallboot-v1. Cross-origin responses from *.github.io are stored as opaque — the browser serves them transparently on navigation but JavaScript cannot inspect their bytes. That's fine for launch-and-use; it means the size readouts for opaque entries are estimated from server content-length or a fixed padding when unknown.

boot from USB · GrapheneOS installer + FallBoot payload

Turn a USB stick into a multi-boot device that carries the GrapheneOS installer and the FallBoot cache. Useful for border crossings, field deployment, or provisioning a fresh device without ever going online.

materials

  • USB 3.0+ stick, 32 GB or larger
  • A Linux or macOS machine (Windows works but the Ventoy CLI is smoother on POSIX)
  • Latest GrapheneOS installer ISO from grapheneos.org/install
  • Ventoy (multi-boot loader) from ventoy.net
  • Portable Chromium build (e.g. ungoogled-chromium) from ungoogled-chromium-binaries

step 1 · install ventoy on the USB

# Linux/macOS
sudo ./Ventoy2Disk.sh -i /dev/sdX     # replace sdX with your USB device

# Windows
Ventoy2Disk.exe → select USB → Install

Ventoy creates two partitions: a small VTOYEFI partition (bootloader) and a large exFAT partition for payloads. Anything you drop onto the exFAT partition is bootable if Ventoy recognises the format (ISO, IMG, WIM, VHD, EFI).

step 2 · drop the GrapheneOS installer ISO

cp grapheneos-installer-*.iso /media/$USER/Ventoy/

step 3 · export the FallBoot bundle

Click Export bundle (.zip) above. The zip contains this page, the service worker, the PWA manifest, and every cached tool's HTML entry.

step 4 · add a portable Chromium + the FallBoot payload

mkdir -p /media/$USER/Ventoy/fallboot
unzip fallboot-bundle.zip -d /media/$USER/Ventoy/fallboot/
cp -r ungoogled-chromium-portable /media/$USER/Ventoy/fallboot/browser/

On any machine that boots the USB (or mounts it as a data drive), the user opens fallboot/browser/chrome.exe --user-data-dir=./profile file:///path/to/fallboot/index.html. The service worker installs on first open; from then on everything runs from the local cache.

step 5 · verify before travel

On the machine you'll leave behind: mount the USB, boot the portable Chromium into index.html, run Verify integrity. Green across the board means the bundle survived the copy. Any coral row means re-export.

border-crossing notes

  • The USB stick alone shows up as a plain storage device. There's no active network stack, no signed-in accounts, no leaked identifiers.
  • Every estate tool inside is local-first (WebLLM, IndexedDB, WebRTC) so no traffic leaves the machine once loaded from cache.
  • GrapheneOS install itself is a separate act — the ISO on the USB gives you the option to reformat the phone but does not do so on its own.
  • If you carry hashes on paper (the Verify integrity output), you can prove on the other side that the bundle wasn't tampered with in transit.

about · FallBoot

FallBoot is a boot entry point. It reads the FallHarbor manifest, shows every estate tool with its offline status, and bundles them all into browser Cache Storage on demand. The result is a portable estate that travels on a USB stick.

Uses only already-shipped estate primitives:

  • FallHarbor — the tool manifest and directory
  • FallStore — content-addressed local cache pattern
  • Cache Storage API + service worker — browser-native offline layer
  • Web Crypto (SHA-256) — integrity checks against a pinned manifest
